# Automatic product gallery

The authorized gallery workflow watches both **public** release versions every five minutes (GitHub scheduling may be delayed) and when version files reach main. Dispatch starts an immediate check. It runs the tracked native capture tour against public application assets, intercepting browser API traffic into a fresh disposable synthetic mock-provider backend checked out at the public application's commit. Service workers and unexpected API origins are blocked. No production login, database, API key, environment or storage is accessed.

The exact current capability image references must match the complete tour output. Capture errors, public identity changes, missing/corrupt images or a changed main tip reject the candidate; no partial candidate is committed or published. A later run retries from scratch. All current image and zoom links receive the new marketing `?v=` query, allowing warmed browsers to retrieve the updated gallery normally. The scenario tree remains first/default.

A validated batch creates a narrowly bounded `codex/automatic-product-gallery-<run>` PR. Its changed named acceptance test binds every image hash and output version. Only this generated PR is selected for auto-merge, under the existing protected-main required Actions check. Because GitHub suppresses token-created PR events, the workflow explicitly dispatches CI on the generated branch at its exact head/base. The repository must allow Actions to create PRs. No rule bypass, force push or arbitrary contributor auto-merge is used. Infrastructure workflow changes continue through standard policy.

After protected merge, the installed immutable UI publisher builds/activates marketing only and retains its previous artifact. The workflow polls all public image hashes using the same versioned links shipped in HTML, matching release identities and application health. A queued follow-up workflow sees its own recorded output marketing version in AUTO_CAPTURE.md and exits without recapturing. A new application version or independently released marketing version triggers a fresh batch. Failed required CI leaves the old gallery live; a pending PR is reported rather than creating duplicates. Close a permanently failed generated PR after correcting the underlying problem to let the next schedule generate a new candidate.

Runtime browser dependencies and native JPEG/provenance artifacts are disposable CI resources; source, ledger and outputs are versioned through main. No backend/DB service is restarted by gallery publication. No new customer rollout is implied.
