# Automatic UI releases

Use a normal work branch with Spec Kit acceptance evidence. An authorized maintainer chooses the PR explicitly with `gh pr merge --auto --merge` (or enables native auto-merge in GitHub). Required checks and protected main still apply. An already-green PR can be merged normally. No automatic approval is granted to contributors.

The server checks GitHub main every 25 seconds, under the existing release operation lock. It considers all paths since its verified cursor. Ordinary React presentation components, CSS, images and static marketing assets qualify. Supporting specs, docs and acceptance tests can accompany the change. Unknown paths, dependencies, frontend services, server routes, deployment policy and backend/database changes require the standard release path. A verified full manual release can advance the baseline. An explicit rollback suspends automatic publishing until a standard release. Build and cutover reuse the existing canary and public verification/automatic recovery path. A failed attempt is latched by SHA. A corrected SHA or an explicitly verified manual release can proceed.

For an eligible PR the required Spec Kit job runs linked critical tests. App UI runs type checks and a production build; marketing-only excludes app builds in GitHub. Extensive product suites remain in the normal CI lane for standard changes. Production staging still enforces its independent checks. Each relevant surface requires a version increment. The VPS records checked source commit, times and scope in the root-owned auto-ui.json journal. The production database and unchanged backend are not started for the fast path.

## Install or update

As the existing VPS administrator fetch the trusted main, pin and review the chosen full SHA. Extract deployment/auto-ui.py, deployment/release.py and deployment/casebridge-auto-ui.{timer,service} from that exact Git object; never execute files from a PR checkout. Install the two Python files under /usr/local/sbin as root-owned mode 0555 (casebridge-auto-ui and casebridge-release), and the two systemd units under /etc/systemd/system as root-owned mode 0644. Validate a sudoers drop-in granting cb-release only `/usr/local/sbin/casebridge-auto-ui ""` via visudo. Provision the root-only journal baseline only after verifying that the live application and marketing runtime sources match the approved baseline (policy-only bootstrap differences must be reviewed). Keep the existing journal when updating. Enable and start casebridge-auto-ui.timer. Disable the timer to pause future work. An already running job can finish under the lock.
