# Claude subagent provider for the owner's own AI requests

Owner request (25 Nov 2026), narrowed by owner decision after checking Anthropic's terms: a Claude subscription `claude setup-token` may only power the subscriber's own use. Anthropic's Agent SDK and legal pages do not allow a product to collect Claude.ai credentials or to route other users' requests through Free/Pro/Max/Ultra plans. So the platform admin stores one setup-token for personal use and names the user accounts it serves (the owner's own logins). Every other user, every firm and the public site cat keep the existing path. Refs GitHub issue #123.

## User Scenarios
1. The platform admin opens Ayarlar, pastes the output of `claude setup-token` into "Claude (setup token)", saves, tests ("Bağlantı çalışıyor.") and picks their own firm-admin login as the account it serves. The card says "Yalnızca kişisel kullanım; büro kullanıcılarına açılmaz."
2. Signed in with that account, the owner uses the case chat, the CaseBridge AI cat's data chat, similar-cases explanations, Sufle, simulations, the courtroom rehearsal, document intake and the legal lab; the chat header shows a "Claude" badge.
3. A lawyer of the same firm, a user of another firm and an anonymous site-cat visitor never touch the token; their requests behave exactly as before.
4. When Anthropic rejects the token, the owner sees "Claude token geçersiz, yenileyin." in the chat and a "Geçersiz" badge in Ayarlar.

### Functional Requirements
- **FR-001**: Only the platform admin can read or change the setup-token and its account list (`/platform/claude-subagent`: GET, PUT /token, DELETE /token, POST /test, PUT /users, GET /users/search); firm admins and lawyers get 403, anonymous 401. There is no per-firm token.
- **FR-002**: The token is stored encrypted with the existing AI-key mechanism (Fernet with `AI_SECRETS_ENCRYPTION_KEY`, 0600 file, atomic replace) in one platform-scope envelope with the account list and status. Responses, audit rows, logs and the page never contain it: only set / last 4 / updated / status / accounts. Saving, removing and changing accounts write platform audit rows without values. Format check `sk-ant-oat01-…`; at most 10 accounts, each active with an accepted invitation.
- **FR-003**: Routing: a request runs on the subagent only when a token is stored AND the requesting user's id is on the list AND the user is active — checked on the server for every request (chat and its level classifier, mascot data chat, analysis/simulation start, similar-cases explanation, case intake, legal lab, Sufle analysis) and for queued simulation and courtroom jobs (by the user who started them). Otherwise the existing provider path is used unchanged. The site cat (`/public/site-chat`) never uses it.
- **FR-004**: Sandbox per run (Claude Agent SDK 0.2.188, bundled Claude Code CLI): no built-in tools (`tools=[]`, built-ins in `disallowed_tools`, permission callback denies anything else), no settings sources, only our in-process MCP server, fresh empty temp directory as cwd/HOME/config (deleted after), 90 s timeout, max 8 turns, one retry only on a 5xx, at most 3 concurrent runs per firm (others wait). The subprocess environment blanks every inherited variable outside a small allowlist (no ANTHROPIC_API_KEY, OpenAI, JWT, encryption or database secrets) and carries the token per call as CLAUDE_CODE_OAUTH_TOKEN, never process-wide.
- **FR-005**: The mascot's 8 read-only data tools run as in-process SDK MCP tools through the existing ChatToolRunner guards: the requesting user's firm only, the REST permission rules, 4 calls per turn, one audit row per call, document text wrapped as data, and no further tool after a tool returned document text. Sources and SSE events are the same as before.
- **FR-006**: Errors map to the existing friendly messages: rejected token → "Claude token geçersiz, yenileyin." and status "invalid"; rate limit → a "kullanım sınırı" message without retry; timeout → time-out message; other failures → "Claude bağlantısı kurulamadı". The existing prompts and no-fabrication guards are passed unchanged.
- **FR-007**: UI: the platform admin's Ayarlar shows the "Claude (setup token)" card (password field, Kaydet, Test et, Kaldır, badge Aktif / Geçersiz / Test edilmedi / Yok, last 4, updated, help "Terminalde `claude setup-token` çalıştırıp çıkan token'ı yapıştırın.", note "Yalnızca kişisel kullanım; büro kullanıcılarına açılmaz.", account search/add/remove). The AI chat header shows a "Claude" or "OpenAI" badge.
- **FR-008**: The backend image installs `claude-agent-sdk==0.2.188` (bundled CLI, ~0.4 GB) and runs `claude --version` at build time; `mcp==1.30.0`, `pydantic==2.11.10` and `uvicorn==0.31.1` keep the dependency set resolvable with FastAPI 0.115.0 / Starlette 0.38.6.

## Success Criteria
- Tests prove: platform-only settings, encryption at rest and no token in responses/logs/audit, routing only for listed active users (requests and queued jobs), firm isolation through the subagent's tools, the tool allowlist and environment scrub, temp-dir cleanup, timeout/invalid-token/5xx-retry/429/concurrency handling, and that the site cat never runs it. The SDK is mocked in CI.
