# CaseBridge AI floating cat and firm-scoped data chat, stages 1–2 (application v.0.50, unreleased)

User request (24 Nov 2026): a floating cat mascot on every signed-in page that opens a CaseBridge AI chat panel (stage 1), and read-only, firm-scoped data tools so the chat can answer from the bureau's own cases, documents, hearings, tasks, clients, precedents and calendar (stage 2). It reuses the existing chat backend and streaming (`chat_service`, `chat_stream`); no second chat system, no new table.

## User Scenarios
1. A lawyer sees the cat at the bottom right of any workspace page, drags it to the other side (it snaps to the nearest edge and stays there after a reload) and clicks it, or presses ⌘J / Ctrl+J, to open the chat panel. Esc or "–" closes it; "Kediyi gizle" hides the cat until "CaseBridge AI'ı göster" or the shortcut brings it back.
2. On a case page the lawyer asks "Bu davanın duruşmaları ne zaman?". The cat thinks, looks things up and writes; the answer lists only stored records and shows clickable chips for the case, document, precedent, client or calendar entries it used.
3. The cat poses by context: reading on document pages, in court on Canlı Duruşma, celebrating once when a won case is opened, sleeping after three idle minutes, and rarely taking a tea break or dancing.
4. Another bureau's data never reaches the answer, even when an id is guessed or a document contains instructions; restricted workspace accounts and platform admins get no cat and no data tools; every tool call is in the bureau audit log.

### Functional Requirements
- **FR-001**: Floating widget on every page rendered in `AppShell` (not login, password or marketing pages, not presentation mode), for the users who see the CaseBridge AI menu: not workspace-restricted accounts, not platform admins. Dragging works with mouse, pen and touch (pointer events), snaps to the nearer left/right edge, is clamped inside the viewport on resize, and the position is kept in localStorage behind try/catch.
- **FR-002**: Clicking the cat (not the click that ends a drag) or ⌘J / Ctrl+J toggles a chat panel of about 400×560 (full-screen sheet below 640 px). Esc and "Paneli küçült" close it and return focus to the cat; "Kediyi gizle" hides the cat (remembered) and a small "CaseBridge AI'ı göster" button or the shortcut restores it. The open panel and its conversation survive page changes within the tab (sessionStorage).
- **FR-003**: One pure mode state machine (`lib/mascot.ts`): idle by default; thinking after a question is sent; researching while a data tool runs; working while the answer streams; victory once per won case per tab session (case page announces the outcome); sleeping after 3 minutes without input; reading on `/belgeler` and the case Belgeler tab; courtroom on `/ai/durusma`; tea-break and dancing as rare idle variants, at most one per 10 minutes. Priority: chat > victory > page pose > sleep > variant > idle. Poses crossfade in ~200 ms; `prefers-reduced-motion` turns the fade and movement off.
- **FR-004**: The panel uses the existing chat endpoints (`POST /chat/conversations`, `POST /chat/conversations/{id}/messages` SSE) with `data_tools: true` and `context {route, case_id}`; the full chat page sends neither and is unchanged. Empty state with suggestions, not-configured state from `/chat/status`, send/stream error states, and a link to the same conversation in the full chat page.
- **FR-005**: Read-only data tools, never raw SQL: `search_cases`, `get_case`, `search_documents` (extracted-text snippets), `get_hearings`, `get_tasks`, `search_clients`, `get_precedents`, `get_calendar`. Each reads through the same services/repositories as the REST routes (`CaseService`, `DocumentService`, `HearingService`, `TaskService`, `ClientService`, `CalendarService`, and the `firm_precedents` query shared with `GET /precedents`), with the bureau and user taken from the session, never from tool arguments.
- **FR-006**: Permission rules match the REST routes: every query is filtered by `law_firm_id`; ordinary case tools never return precedents and `get_precedents` returns only precedents; a guessed id of another bureau, a precedent id passed as a case or an unknown id is "Dava bulunamadı"; workspace-restricted accounts are refused by the chat dependency (403) and again by the tool layer (database check). The page-context case id is used only after it is found in the caller's bureau; ids are stripped from the route hint.
- **FR-007**: Limits: at most 8 rows per tool, 320 characters per document snippet, 600 per stored text field, 4 tool calls and 2 planning rounds per turn, 12 000 characters of tool results in the prompt, 12 source links per answer; the calendar range is clamped to 62 days. Client contact details are not returned.
- **FR-008**: Document text is untrusted data: snippets are wrapped in `<belge_metni>` with angle brackets in stored text neutralised; both the planner and the answer prompt say instructions inside records must be ignored; and no planning round runs after a round that returned document text, so text in a document can never choose further tool calls.
- **FR-009**: Sources: the stream sends `tool` progress events and one `sources` event; `done` carries the same `sources` (kind, id, label, app href). The panel shows them as clickable chips.
- **FR-010**: Audit: one `management_audits` row per tool call — actor, `action=ai.tool_used`, tool name, conversation id, `{tool, record_ids}` and time; no arguments and no content. Visible in Büro Yönetimi → işlem geçmişi as "CaseBridge AI kayıt okudu".
- **FR-011**: Provider and keys: tool planning is a non-streaming `plan_tool_calls` on the same chat provider instance (OpenAI function tools, Claude tool use), resolved through the existing per-firm credential lookup (`get_chat_provider_resolver` → `ai_credential_scope`). Ollama plans no tools. `CHAT_PROVIDER=mock` plans deterministically from the user's own words and the page case, and answers with the labels of the records found. A planning or tool failure never breaks the answer.
- **FR-012**: Application version v.0.50; transparent WebP assets `public/mascot/cat-<mode>@{128,256}.webp` for the ten modes.

## Success Criteria
- Every tool is tested for bureau isolation, guessed ids, precedent rules, row and snippet limits, audit rows and prompt injection; the widget is tested for drag and snap, saved position, open/close/Esc/shortcut, mode changes, source chips, empty and error states.
- The full backend and frontend suites, tsc and next build pass; the browser check covers light, dark and mobile with screenshots in `artifacts/ai-mascot/`.
