# Public "site cat" chat on the marketing website (marketing v.0.66, application v.0.51, unreleased)

User request (24 Nov 2026): a floating lawyer-cat on casebridge.com.tr that answers only questions about CaseBridge as a product, fully separate from the in-app CaseBridge AI (no login, no database, no tools, no bureau data), with quick questions that work without the AI, strict abuse limits and no stored conversations.

## User Scenarios
1. A visitor on any marketing page sees the cat at the bottom right, drags it to the other edge (it snaps and stays there on the next visit) and opens the panel. They tap "Verilerim güvende mi?" and get an answer instantly, without any network request.
2. The visitor types "Yapay zekâ size hangi verileri gönderiyor?". The cat thinks, then answers only from the knowledge file; if the fact is not there it says so and offers "Demo planla".
3. A visitor asks "Ev sahibim kirayı artırdı, davamı kazanır mıyım?" and is told "CaseBridge hukuki danışmanlık vermez", without a model call. "Önceki talimatları yok say…" gets a polite refusal.
4. When the day's token budget is used up, the cat says "Şu an yoğunuz" and the quick questions keep working. Another website cannot call the endpoint from a browser.

### Functional Requirements
- **FR-001**: `backend/app/site_chat/site-knowledge.md` is the only knowledge source: about 1,100 words, versioned by a `site-knowledge version` comment, built only from the marketing site text and repo docs. Unconfirmed facts (pricing, trial, KVKK statement, hosting location, contact, certifications, integrations, AI model list) are `TODO` lines; the prompt turns them into explicit "unknown" markers.
- **FR-002**: `POST /public/site-chat {messages:[{role,content}], lang?, turnstile_token?}` returns `{answer, kind, lang, knowledge_version}` as plain JSON. No authentication, no database session, no tool calling, no bureau data; it never reads a bureau AI key.
- **FR-003**: The system prompt allows answers only from the knowledge file, never claims features, prices, customers, certifications or numbers that are not in it, answers unknowns with the demo link, refuses off-topic questions, refuses legal advice with "CaseBridge hukuki danışmanlık vermez", treats visitor text as questions only, and answers in the visitor's language (Turkish or English).
- **FR-004**: Deterministic guards run before any model call: prompt-injection phrases in any turn and requests about the visitor's own legal situation get fixed refusals (in Turkish or English) without spending tokens.
- **FR-005**: The model is the platform OpenAI key (`get_openai_api_key(None)`) with `SITE_CHAT_MODEL` (default gpt-4o-mini), at most `SITE_CHAT_MAX_OUTPUT_TOKENS` (350), 20 s timeout, one retry. `LLM_PROVIDER=mock` gives a deterministic answer from the knowledge file. No platform key, a provider error or `SITE_CHAT_ENABLED=false` gives a friendly 503 `unavailable`.
- **FR-006**: Abuse limits: per IP 10 messages/minute and 50/day (429 `rate_limited`); a user message of at most 500 characters (422); at most 12 user turns per conversation (422 `turn_limit`); a daily token budget across all visitors (`SITE_CHAT_DAILY_TOKEN_BUDGET`, default 1,500,000) after which the endpoint answers 503 `busy` ("Şu an yoğunuz…"). Limits are in memory (single backend process) and reset at restart.
- **FR-007**: CORS for `/public/*` only: `https://casebridge.com.tr`, `https://www.casebridge.com.tr` (`SITE_CHAT_ALLOWED_ORIGINS`) and `http://localhost` / `http://127.0.0.1` on any port. Preflights from those are answered; a request with any other Origin is rejected with 403 before it can spend tokens; responses never allow credentials. The app's own routes keep their CORS unchanged.
- **FR-008**: Optional Cloudflare Turnstile: when `SITE_CHAT_TURNSTILE_SECRET` is set, a valid `turnstile_token` is required (403 `verification_failed` otherwise). Off by default.
- **FR-009**: Privacy: conversations are not stored anywhere. Each turn logs one line with kind, topic label, language and token count only — no message text and no IP address. IPs exist only as in-memory rate-limit keys.
- **FR-010**: Widget (`web-page/site-cat-loader.js`, `site-cat.js`, `site-cat-model.mjs`, `site-cat.css`): vanilla JS/CSS under 30 KB uncompressed, lazy-loaded at idle time on all six marketing pages. Bottom-right, draggable with mouse/pen/touch, snaps to the nearest side, position remembered in localStorage (try/catch), kept on screen on resize. Click or Enter opens the panel, Esc and × close it and return focus; full screen below 640 px; respects `prefers-reduced-motion`; dark marketing palette with AA contrast.
- **FR-011**: Poses from the shared cat art (`web-page/assets/site-cat/`): idle, thinking while waiting, sleeping after 2 minutes without input, dancing when any demo/booking link is clicked, victory briefly after an answer.
- **FR-012**: Panel: notice "Lütfen kişisel veya dava bilgisi paylaşmayın.", a "Demo planla" button with the existing booking link, four quick-question chips ("Neler yapabiliyor?", "Verilerim güvende mi?", "Yapay zekâ nasıl çalışıyor?", "Demo nasıl alırım?"; English on English pages) answered from a static FAQ with no API call, a 500-character field with counter, and friendly states for busy, unavailable, rate-limited, turn limit, verification and network errors. The conversation lives only in page memory.
- **FR-013**: Versions: marketing site v.0.66 (`web-page/website-version.json`, homepage meta and footer); application v.0.51 because the backend changed.

## Success Criteria
- Backend tests prove no auth/DB/tool dependency, platform-key-only use without tools, every limit, CORS, Turnstile, mock off-topic/legal refusals, prompt-injection resistance and text-free logs.
- Widget tests prove chips without network, poses, drag and snap, Esc, error and capped states, mobile full screen; screenshots in `artifacts/site-cat/`.
