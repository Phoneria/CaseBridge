# Night Atlas marketing redesign

## User Scenarios
A law-firm visitor explores one explicitly fictional receivables dispute: inspect historical documents, compare two conditional branches, answer a branch-specific rehearsal question, then choose a bureau/lawyer to inspect portfolio/workload/calendar. A real demo request opens the existing appointment service. This is a marketing demonstration, not the admin application.

### Functional Requirements
- **FR-001**: Replace only the marketing homepage with the user-approved Night Atlas world: navy, turquoise graph, paper document and amber critical finding, retained CaseBridge logo and self-hosted type. Four values must have equal, findable sections. Exact Turkish hero and primary exploration CTA follow the approved brief.
- **FR-002**: Draw a genuine depth-tested perspective WebGL graph with nodes in three dimensions, user rotation/drag, pause, DOM/keyboard node access and a meaningful static fallback. Never capture wheel/touch vertical scrolling. Pause outside the viewport/background; reduced-motion starts static.
- **FR-003**: Keep one fictional case across document timeline, two branch states, distinct question/options/feedback and bureau/lawyer workload/calendar. No invented/calibrated winning percentages, external AI call, persistence, customer data, or fake submission.
- **FR-004**: Demo talep et opens the existing real calendar appointment URL; retain app login and secondary marketing destinations. Turkish/English navigation/content work. Preserve keyboard focus, readable contrast, responsive layouts, native scrolling and no-JS core content.
- **FR-005**: Verify model, browser interactions, visual quality, WebGL fallback/reduced motion, widths 320/390/768/1024/1440, asset integrity and performance. Publish only marketing through the existing main-sourced immutable release path, increment its separate v. version and verify public code/version/health while app containers/version stay unchanged.

- **FR-006**: Explicitly disable the retired native screenshot-gallery capture in the marketing manifest. Detection must skip before any app/network/capture/publication; keep existing gallery assets and generic capture-tool validation intact.

## Success Criteria
All four values and the full fictional journey are accessible by keyboard and touch. Both branch choices change question/feedback; bureau/lawyer change real displayed demo counts and tasks. No overflow, scroll lock, missing assets or console errors. Public proof precedes a deployment-complete claim.
